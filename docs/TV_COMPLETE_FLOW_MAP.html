Flow Map Node Explainer — Trade Vision Complete Flow Map (v1.94)

Canonical source: this HTML file only (Tab 3). Optional offline MD copy may exist; HTML wins.

Audience: New developers, product managers, AI assistants

Goal: Understand each block in under ~60 seconds · Date: 2026-07-25

1. Executive summary

Trade Vision is a paper trading guidance product: it helps an operator look at market candles, run a fixed analysis pipeline, and (optionally) record a simulated trade — not a real broker order.

Money is never live: SYSTEM_MODE is MOCK and live trading is blocked.

The main path is: open app → pick stock settings → Analyze → freeze safe candles → run evidence engines → judge (Arbiter) → Opening Range (ORB) setup → judge again → show guidance → optional human Record → optional Observe result.

Other blocks (Jarvis panels, Kronos, Twin, Gemini/Grok, TrendForge, OpenAlgo, Stock App, regime/lag APIs) are side systems: they can research or display, but they do not own the paper final decision band.

2. Node entries (all 24, by kind)

Kind: data (candle IN → result OUT)

① CANDLE SOURCE | local 1m bars (candle_src)

FieldDetail
What is it?The place where raw price bars first enter the paper Analyze path — a download of one-minute candles for the lab stock.
Kinddata
PurposeGive the app real OHLCV numbers (open, high, low, close, volume) so nothing is inventing prices.
What it actually does1. On Analyze, UI requests lab candles. 2. Backend returns an array of 1-minute bars. 3. Bars stay in memory for this request (not the paper ticket store).
When does it run?User click Analyze on the ORB Paper Guidance card.
Who uses it?UI BUILD turns bars into a multi-timeframe payload. Operator does not edit raw bars by hand.
Key files / APIsGET /api/v1/behavior/data/local/reliance-1m/preview · client.behaviorImportLocalReliancePreview · App.tsx runOrbGuidance
Why was it created?Need a reliable offline/lab feed of closed bars without depending on a live exchange feed for paper guidance tests.
Simple analogyLike downloading today’s weather readings before deciding whether to take an umbrella.
Important noteLab path often forces RELIANCE 1m even if the room symbol is different. Not a live broker feed.

② UI BUILD | App.tsx payload (ui_build)

FieldDetail
What is it?Frontend code that reshapes 1-minute bars into the exact package the backend expects.
Kinddata
PurposeBuild higher timeframes and a decision time so analysis only uses finished candles.
What it actually does1. Takes 1m bars. 2. Resamples NSE session into 5m / 15m / 1H. 3. Trims to closed candles. 4. Sets decision_time_ns. 5. Builds PaperGuidanceRequest (symbol, timeframe, series, higher_timeframe_series, direction, include_orb_playbook).
When does it run?Immediately after candle import, still inside Analyze.
Who uses it?HTTP IN posts this package. Called from App.tsx helpers (buildOrbGuidancePayload).
Key files / APIsApp.tsx buildOrbGuidancePayload, resampleNseSeries · models PaperGuidanceRequest
Why was it created?Backend needs multi-timeframe closed bars and a single decision clock; UI owns the lab assembly.
Simple analogyLike chopping vegetables and packing a lunchbox before you send it to the kitchen.
Important noteHigher-timeframe bars travel in the same POST body — not a separate versioned HTF database.

③ HTTP IN | POST /paper-guidance/run (http_in)

FieldDetail
What is it?The API door where the browser sends the candle package to Python.
Kinddata
PurposeOne official entry for “run paper guidance now.”
What it actually does1. Accepts JSON body. 2. Calls run_paper_guidance_with_orb with SYSTEM_MODE and KILL_SWITCH. 3. Returns an envelope with guidance.
When does it run?On Analyze after payload build.
Who uses it?Frontend client.paperGuidanceRun. Operators never call it by hand in normal use.
Key files / APIsPOST /api/v1/paper-guidance/run · main.py paper_guidance_run · client.ts
Why was it created?Single product route so UI and tests share one spine instead of many ad-hoc analyzer endpoints.
Simple analogyThe front desk window where you hand in your form.
Important noteHTTP only on this path (no WebSocket). Live trading flags stay blocked in mode/kill/safety.

④ D2 SNAPSHOT | SHA-256 hash (snapshot)

FieldDetail
What is it?A frozen copy of “only fully closed candles” plus a fingerprint so every later step uses the same picture of the market.
Kinddata
PurposeStop future-looking leakage and make results reproducible for this decision time.
What it actually does1. After quality + PIT + D1 safety. 2. Keeps bars whose open+duration ≤ decision time. 3. Builds canonical JSON of symbol/TF/decision_time/bars. 4. snapshot_hash = SHA-256(hex) of that JSON.
When does it run?Early inside every successful /paper-guidance/run (after gates pass).
Who uses it?Evidence pack, ORB core, tickets, paper records all bind to this hash.
Key files / APIspaper_guidance_spine.freeze_d2_closed_candle_snapshot · hashlib.sha256
Why was it created?Without a freeze, engines could disagree about which bars “count.”
Simple analogyTaking a Polaroid of the board mid-game and only analyzing that photo.
Important noteIf D1 fails, no snapshot — pipeline returns blocked guidance.

FieldDetail

Who uses it?UI screen out; optional paper store on Record.
Key files / APIsmodels.PaperTradeGuidance · ticket file data/orb_guidance_tickets.json
Why was it created?Product needs one typed object, not many competing analyzer outputs.
Simple analogyThe final exam grade report: pass/watch/enter + why.
Important noteIncludes safety literals like live_trading_blocked=true, trade_allowed=false. Not a broker order.

FieldDetail

3. How the blocks talk to each other

Candle source → UI build → HTTP IN — Lab 1m bars become a multi-TF PaperGuidanceRequest and POST to /paper-guidance/run.

HTTP IN → Snapshot — P0 quality/PIT/D1 then freeze closed bars + SHA-256 hash.

Snapshot → Evidence pack — Same frozen bars feed the eight sequential spine engines (receipts, degraded-on-error).

Snapshot → ORB core — Same hash/series used to build opening-range setup if an active playbook exists.

ORB offline → ORB core — Discover/prove/promote write playbooks JSON that /run later lists.

Evidence + ORB → Arbiter → Guidance out — Judge merges scores/authority into final_band + PaperTradeGuidance.

Guidance out → UI screen out — Card shows band/plan/blockers to the human.

Guidance out → Paper store (optional) — Human Record with ticket id + phrase + hash → local simulated ledger.

Paper store → Outcome out → UI — Observe later bars → outcome/reliability redrawn on card.

Side systems → Jarvis → UI — Kronos/AI/Twin/TrendForge/OpenAlgo/9C display only; safety blocks live and OpenAlgo routing.

## 4. Step-by-step walkthrough (user story)

You open Trade Vision in the browser. The shell (ui) loads; you switch to Jarvis. Mode is practice: live trading is off (safety).

You set timeframe and direction on the ORB Paper Guidance card. Today, Analyze still pulls lab RELIANCE 1-minute candles (candle_src) even if the room symbol differs. The UI builds higher timeframes and a decision clock (ui_build), then POSTs everything to the backend (http_in).

The server checks quality and point-in-time safety, runs nine D1 safety checks, and freezes a D2 snapshot with a SHA-256 fingerprint (snapshot). If anything fails, you only get a blocked/wait-style guidance.

If it passes, the evidence pack runs its fixed engine list — chart, candle condition, levels, snapshot indicators, multi-timeframe, memory, liquidity, OI/risk — each filing a report. Kronos and AI do not get a vote score here.

The arbiter judges once without an entry plan (often stays WATCH). Then ORB loads an active playbook (from earlier offline discover/prove work) and proposes entry/stop/target. The arbiter judges again; only then might you see ENTER_PAPER.

You see the result on the ORB Paper card (ui_out / guidance_out). If not eligible, you stop. If eligible, you confirm Record: the server checks ticket freshness (~15 minutes) and stores a simulated paper row (paper_store) — still no broker, no Stock App auto-fill.

Later you Evaluate: later closed bars measure the paper outcome (outcome_out), and reliability/storage health refresh on the card.

Meanwhile, Jarvis may show Kronos, Gemini/Grok, Twin, TrendForge intakes, OpenAlgo previews, or 9C panels — useful side screens, not the paper band boss. When you are done, the cycle ends; live trading never turned on.
